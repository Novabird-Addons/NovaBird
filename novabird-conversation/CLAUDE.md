# NovaBird-Conversation – Projektkontext für Claude Code

Neubau einer Konversationsansicht („Gmail Conversation View“) für Betterbird / Thunderbird ESR (getestet mit Betterbird 153 ESR, `strict_min_version` 128). ID `novabird-conversation@novabird`, Anzeigename „NovaBird-Conversation“, früher „Conversation-Pilot“ (`conversation-pilot@local`, bis 0.12.0). Orientiert am Add-on „Thunderbird Conversations“ (ATN „Gmail Conversation View“, MPL-2.0; nur gelesen, kein Code übernommen). Sprachen DE, EN, FR, ES.

## Ordner und Bauen
- Quelle ist dieser Ordner. Build: `./build.sh` → `../../Release/Kandidaten/novabird-conversation-<Version>.xpi` (packt manifest.json, settings.js, conversation.js, background.js, _locales, icons, content, experiments, options; nicht tests, beschreibung). Kandidaten tragen `RC`; Freigabe nach `../../Release/` nur auf Wort des Nutzers. Jede Änderung: Version in `manifest.json` erhöhen.
- Beschreibung für Nutzer: `README.md` (bei neuen Funktionen und Versionsnummer mitpflegen). Screenshots später neu, nur mit erfundenen Daten ohne echte Namen/Adressen.
- Tests: `node --check` auf die JS-Dateien und `node --test tests/conversation.test.js tests/locales.test.js` (`node --test tests/` allein geht nicht; 22 Tests). Neue Texte immer in allen vier Sprachen (`_locales/{de,en,fr,es}`); `tests/locales.test.js` prüft Schlüssel, Platzhalter, Verwendung. Betterbird-Test im Labor `../../Testlab/novabird-conversation/` (Port 4000, `README.md`): `convtest.py`, `permtest.sh`.
- Abhängigkeiten: optional **NovaBird-DB** (`novabird-db@novabird`, Konversation aus dem Index in Millisekunden). Die **NovaBird-Extension** liest den DOM dieses Add-ons (Chips `.nbc-chip`, Karten `.nbc-card`, Absender `.nbc-name`) für die Anhang-Vorschau – diese Klassennamen nicht ohne Abstimmung ändern.
- Neue ID = neues Add-on: Einstellungen (`storage.local`, Schlüssel `settings`) beginnen leer; das alte Add-on vorher entfernen.

## Ziel und Verhalten
Alle Nachrichten einer Konversation (über alle Ordner) im Lesebereich gruppiert: neueste oben fixiert, ältere darunter (Option „älteste zuerst“); Auto-Aufklappen (neueste + vorherige + ungelesene + gewählte), Rest als Zeile mit Vorschau; Höchsthöhe der fixierten Nachricht mit „Ganz anzeigen“; je Nachricht Header mit Knöpfen „Original“ und „Spam“; Anhänge als Chips; cid-Bilder im Text; Zitate hinter „…“; Aktionen Antworten/Allen antworten/Weiterleiten/Als Anhang/Als neu bearbeiten/Löschen (nur Papierkorb)/Spam; Betterbirds Standardkopf wird ausgeblendet (`hideHeader`), Einzelmails ohne Konversation behalten die Standardanzeige (`alwaysRender`); drei Stile Sanft, Klar, Faden; Animationen einstellbar (0 = aus, „Bewegung reduzieren“ respektiert); externe Bilder mit Hinweis und Menü (nur diese Nachricht / Unterhaltung / immer von diesem Absender); Fallback „Original“ (auch automatisch bei unlesbaren Mails). Tastatur und „als gelesen markieren beim Aufklappen“ bleiben bei den Betterbird-Standards. Leitbild: möglichst alles lokal, nichts auf Vorrat per Netz laden.

## Architektur
- `background.js`: antwortet auf `hello` des Anzeigeskripts (je Tab: `sender.tab.id`, `getDisplayedMessage(tabId)`); Quellenkette **NovaBird-DB → Gloda → `messages.query`** (`engine`: auto | db | gloda | query); Zwischenspeicher je Konversation (60 s) und je Nachrichtentext (40), geleert bei Postfachänderungen; `resolveId`, `runAction` (reply, replyAll, forward, forwardAsAttachment, editAsNew, openAttachment, delete, junk/notJunk), `body`, `image`, `cidImage`, `allowSender`, `header`; Status-Push der DB (`onMessageExternal`, Absender `novabird-db@novabird`).
- `conversation.js`: reine Logik (Node-testbar): `normalizeSubject`, `groupConversation` (Union-Find über Message-ID/References/In-Reply-To, Betreff-Ersatz `off|subject|smart`), `pickExpanded`, Index-Zeilen (`rowKey`, `dedupeRows`, `rowToView`), `dedupeByMid`, `addressesOf`.
- `settings.js`: `SETTINGS_DEFAULTS` + `sanitizeSettings`. Schlüssel u. a.: style, order, pin, maxHeight, expand, attachments, collapseQuotes, alwaysRender, fallback (+fallbackDays, fallbackPeople), engine, limit, hideHeader, stickyHeader, rowLines, autoOriginal, autoOpen, openMs, fadeMs, debugTiming.
- `content/view.js` + `view.css`: per `messageDisplayScripts.register` (Permission `messagesModify`) ins Nachrichtendokument injiziert; ersetzt `document.body`; Stilblätter und `<body>`-Attribute der Mail werden abgeschaltet; HTML per DOMParser in eine Whitelist kopiert (kein Skript, keine Stile). Klassen `nbc-*`, Variablen `--nbc-accent/-border/-tint`, Messpunkte `data-nbc-timing`/`data-nbc-bg` am Dokument (mit `debugTiming` auch in der Konsole).
- `experiments/conversationView/` (Name unverändert): `setHeaderHidden`, `getThemeColors`, `getReferences`, `getOfflineState`, `getMessageId`, `getGlodaConversation`, `getAllowedSenders`/`allowSender`, `fetchImage` (über das Hauptfenster: ohne Cookies/Referrer, ≤ 5 MB, 10 s, png/jpg/gif/webp, als `data:`; im Experiment-Bereich gibt es kein `fetch`/`btoa`).
- `options/`: Reiter „Einstellungen“ und „Aussehen“; Änderungen wirken sofort; Optionen mit Erklärung und Skizzen (inline SVG). Aufklappen beim Scrollen (`autoOpen`): `autoOpenTrigger` scroll|hover, `autoOpenDelay` 50–200 ms (Zeiger bleibt auf einer zugeklappten Zeile, dann klappt genau diese auf).

## Schnittstelle zu NovaBird-DB
- `runtime.sendMessage("novabird-db@novabird", {type:"conversation", headerMessageId, folderId, fallback…, limit})`; erlaubt sind dort für diese ID nur `ping` und `conversation` (Rechteliste `ALLOWED_EXTERNAL` im DB). Zeitlimit 300 ms, Ergebnis 5–70 ms. Die Anfrage selbst ist die Prüfung (kein periodischer `ping`): Fehler → Pause 30 s/2 min/10 min und sofort Rückfall; `ok:false,usable:false` → 60 s; Status-Push `{type:"status", usable, version, api, broken}` hebt die Pause auf. Ordner-Kennung im DB-Format `<accountId>:<Pfad>`.
- Gruppierungsregeln müssen mit der DB übereinstimmen (Details und Tests dort, `../novabird-db/CLAUDE.md`).
- Quellen: Antwortketten gelten zuerst; Betreff-Ersatz nur für Mails ohne Kette (`subject` Standard, `smart`, `off`; gilt für DB und `messages.query`, nicht für Gloda); Papierkorb/Spam raus (außer der gewählten), Dubletten einmal, gewählte Nachricht kommt immer dazu. Gloda: Zeitlimit 900 ms/1,2 s.

## Offline-/IMAP-Konzept
Lokale Nachrichten: Text und Vorschau sofort. Nicht lokale: Wolken-Symbol, kein Abruf auf Vorrat; automatisch nur neueste, vorherige und gewählte, Rest beim Aufklappen; Texte max. 3 gleichzeitig, 45 s Zeitlimit. Anhänge holt Betterbird beim Klick.

## Stolpersteine
- Python-Bearbeitung per `s.index(a)…s.index(b)` kann dazwischenliegenden Code löschen (so ging einmal `setAll` verloren): nach größeren Ersetzungen Funktionen gegenprüfen.
- Regex für versteckte Stile braucht Lookbehind `(?<![\w-])`, sonst trifft `color:transparent` auch `background-color:transparent`.
- `animation-fill-mode: both` macht die Karte zum Bezugsrahmen für `position: fixed` → `backwards`. Animationen starten erst nach zwei `requestAnimationFrame`.
- Scroll-Aufklappen nicht auf Nutzereingaben gaten, sondern Aufbau/eigenes Aufklappen ausnehmen. `getMostRecentWindow` nicht zur Zuordnung nutzen; alles je Tab.
- Headless-Test: **nie echte Verfassen-Fenster öffnen** (mehrere beenden die Instanz); Nachrichten-Tabs laden headless nicht; dieselbe Mail erneut wählen lädt das Dokument nicht neu; Experiment-Änderungen brauchen frischen Start; eingebettete Optionsseite hat im Headless-Profil kein `messenger`.
